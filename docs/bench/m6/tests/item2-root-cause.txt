# Reading GTK 3.24.49 gdk/gdkwindow.c (gdk_window_begin/end_paint_internal) and gdk/x11/gdkglcontext-x11.c:
# once a GtkGLArea is realized the toplevel keeps a gl_paint_context, so every later frame is composited
# with GL, and the cairo paint surface (an xlib surface) is read with GLX_EXT_texture_from_pixmap
# (gdk_x11_gl_context_texture_from_surface). GDK_GL=software-draw-surface disables exactly that read and
# removes the bug, so the read path is the culprit. The non-GL path does a cairo_paint from the paint
# surface (which flushes it); the GL path does not flush it. Flushing the target after our blit in
# TerminalView::onDraw (cairo_surface_flush(cairo_get_target(cr))) fixes it: see item2-ux-with-fix.txt.
